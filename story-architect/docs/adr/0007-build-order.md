# ADR-0007. Порядок работ: вертикальный срез

**Статус:** принято (подтверждено заказчиком) · **Дата:** 2026-09-15
**ТЗ:** п. 84, 85, 90

## Решение
Сначала доводится до рабочего состояния полный 21-шаговый сценарий
из п. 85 — каждая сущность в минимальном объёме, но цикл замыкается
end-to-end. Затем каждый слой наращивается до полного объёма ТЗ.

Разбивка на 8 спринтов из п. 84 сохраняется как описание состава работ;
порядок постройки задаёт п. 90.

## Обоснование
Главный риск проекта — связка «план главы → Context Pack → черновик →
проверка связности». Если она не работает, узнать об этом нужно на первой
неделе, а не на пятом спринте. Горизонтальный порядок даёт через месяц
полную базу данных, в которой ни разу не написана глава.

## Контроль
Приёмочный сценарий из 21 шага пишется как e2e-тест до кода. Пока тест
красный — MVP не сдан.
