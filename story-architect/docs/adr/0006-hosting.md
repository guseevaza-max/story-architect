# ADR-0006. Хостинг и аутентификация

**Статус:** принято · **Дата:** 2026-09-15

## Контекст
Заказчик: домен свой либо Supabase; пользователь пока один; срок — как
можно скорее.

## Решение
- База данных: **Supabase Postgres** — выбрано заказчиком 15.09.2026.
  pgvector доступен из коробки. Требуются две строки подключения:
  `DATABASE_URL` через пул (6543) для приложения и `DIRECT_URL` (5432)
  для миграций Prisma — через pgbouncer миграции не проходят.
  Инструкция: `docs/supabase-setup.md`.
- Изоляция данных — на уровне приложения (`Project.userId`), не через
  Row Level Security: доступ к базе идёт только с backend. При переходе
  к публичному сервису решение подлежит пересмотру.
- Приложение: Vercel или тот же VPS. Привязки к платформе нет.
- Аутентификация: **Auth.js (NextAuth v5)**, email + пароль, своя таблица
  пользователей. Supabase Auth не используем, чтобы не расщеплять данные
  между двумя системами и не зависеть от вендора.

## Обоснование
При одном пользователе и сжатом сроке важнее скорость развёртывания.
Решение остаётся переносимым: смена хостинга не затрагивает код.
