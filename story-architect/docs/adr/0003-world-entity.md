# ADR-0003. Единая сущность WorldEntity

**Статус:** принято, согласовано с заказчиком · **Дата:** 2026-09-15
**ТЗ:** п. 16, 71

## Решение
Локации, фракции, системы, организации, цивилизации, виды, технологии,
магия, артефакты, исторические периоды, концепции и внешние силы хранятся
в одной таблице `WorldEntity` с полем `type`.

Типоспецифичные данные — в поле `attributes` (JSONB), валидируемом
отдельной Zod-схемой на каждый тип. Десятки nullable-колонок не
добавляются (условие заказчика).

Если для какого-то типа понадобятся собственные связи или индексы —
заводится связанная таблица с внешним ключом на `WorldEntity`, а не
расширяется общая.

## Обоснование
У всех типов идентичный жизненный цикл: статус канона, версии, провенанс,
шлюз предложений, участие в Context Pack. Отдельные таблицы дали бы
тринадцать копий одного кода. Перечень п. 71 (три таблицы) не покрывает
тринадцать типов из п. 16 — единая сущность покрывает.
