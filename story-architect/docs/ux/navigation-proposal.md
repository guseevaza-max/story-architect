# p35 · Предложение по навигации

Основа: [function-inventory.md](function-inventory.md), [duplication-audit.md](duplication-audit.md).
Это проект на согласование: код не менялся.

## 1. Что не так сейчас

- Главная страница проекта — сетка из 15 карточек одинакового веса (`P/page.tsx`). «Предложения AI», где принимаются решения, стоит наравне с Экспортом и Расходами.
- Из рабочих страниц нет постоянной навигации: чтобы попасть из Characters в Proposals, надо вернуться на главную проекта (в `PageShell` только «← Назад в проект»).
- Пять страниц (Characters, World, Relationships, Plot Lines, Timeline) только читают данные, а изменения туда приходят из другого экрана.
- Нет экрана «что делать дальше»: статус каждой главы виден только на списке глав.
- AI Usage вынесен из проекта, ссылка «← На главную» ведёт не в проект.

## 2. Целевая структура (вариант из ТЗ, принят как основа)

Постоянная верхняя навигация проекта (в существующем `P/layout.tsx`, который уже оборачивает все страницы проекта и держит панель Coauthor) и пять основных направлений:

| Направление | Что внутри | Текущие экраны |
|---|---|---|
| **Рабочий стол** | состояние проекта, следующий шаг, ожидающие решения, расход | сейчас `P/page.tsx` (сетка карточек) |
| **Книги и главы** | список глав, рабочее пространство главы (см. chapter-workflow.md) | `chapters`, страница главы |
| **Вселенная** | Материалы (Story Bible, Lore, Референсы), Сущности (Персонажи, Мир, Отношения), Canon (факты), Память | `story-bible`, `lore`, `references`, `characters`, `world`, `relationships`, `canon`, `memory` |
| **Сюжет** | Сюжетная карта (вехи, тайны, замысел книги), Сюжетные линии, Хронология | `plot-map`, `plot-lines`, `timeline` |
| **Центр решений** | ожидающие предложения, открытые вопросы, история решений | `proposals` |

Дополнительно:
- **Coauthor** — плавающая панель на всех страницах проекта (как сейчас). На странице главы она должна принимать фрагменты (как сейчас) и получить режим критика по текущей главе.
- **Инструменты** (меню справа): Экспорт PDF, Расходы ИИ (с возвратом в проект), позже — настройки проекта.

### Альтернатива, которую стоит рассмотреть

«Референсы» в ТЗ не названы ни в одном направлении. Я бы поместил их в **Вселенная → Материалы**, потому что они входят в замысел (Авторский замысел выбирает из них). Если автору нужно быстро менять референсы из рабочего пространства главы, достаточно ссылки из этапа «Замысел».

Альтернатива направлению «Центр решений» как отдельному разделу: держать счётчик ожидающих предложений в шапке и в рабочем столе, а полный список — отдельной страницей. Это то же самое по смыслу, но подчёркивает, что решения принимаются **по месту** (в главе), а не только в центре. Рекомендую именно такую комбинацию (счётчик везде + встроенное принятие в главе + центр как полный список).

## 3. Единая карточка сущности

Цель: на вопрос «что известно о Каэле» отвечать одним экраном.

Состав карточки (чтение, ни одного нового поля в БД для первой версии):

| Блок | Источник данных | Заметки |
|---|---|---|
| Заголовок и статус | `Character`/`WorldEntity`/`PlotLine`…: `name`, `status`, `canonLevel`, `tier` | бейдж «Canon / Предложение / Черновик» |
| Описание, цели, страхи, убеждения | поля сущности | как сейчас на странице Characters |
| Факты | `CanonFact` по `entityType` + `entityId` | с окном действия (`validFromChapter`…), пометка `negation` |
| Состояние по главам | `CharacterState` | таймлайн по главам |
| Отношения | `Relationship` (с историей изменений) | как «Действующие» + «История» сейчас |
| События | `Event`, связанные по главе/участникам | |
| Тайны, которые знает/не знает | `Secret` + (будущее) `KnowledgeFact` | только как чтение; `KnowledgeFact` пока в коде не используется |
| Источники | `sourceChapterId`, `sourceProposalId`, `sourceAiRunId`, `factSource`, `confidence` | ссылки на главу, на решение в Центре решений, на AI-запуск |
| Ожидающие правки | `Proposal` по `entityType`/`entityId` со статусом PENDING | кнопка «рассмотреть» ведёт к тому же action-маршруту |

**Изображений в схеме нет**: ни одного поля `image/avatar` в `schema.prisma` (подтверждено поиском). Блок изображений потребует отдельной миграции и решения о хранении файлов; в первую версию карточки не входит (**необязательно**).

Правила карточки (иначе она ослабит Canon Gate):
1. У каждой строки виден статус «утверждено / предложено / неуверенно / конфликт».
2. Правка из карточки создаёт **Proposal**, а не пишет в сущность напрямую.
3. Предложения ИИ отделены визуально от Canon.

## 4. Рабочий стол

Содержимое без обращений к ИИ (только чтение БД и AI Usage):
- Состояние книги: главы по статусам (IDEA…CANON), слов написано, цель.
- **Следующая задача**, вычисляется правилами: нет плана → «Запустить Architect»; есть ожидающее предложение главы → «Рассмотреть предложение»; есть план без сцен → «Запустить Scene Planner»; сцены есть, черновика нет → «Запустить Writer или писать вручную»; черновик есть, проверка не делалась → «Проверить»; APPROVED → «В Canon»; CANON без Memory Update → «Обновить память».
- Ожидающие решения: число Proposals со статусом PENDING по типам.
- Расход ИИ за месяц из AI Usage (уже есть `/api/ai-usage`).
- Ссылки на последние беседы Coauthor.

Правило: рабочий стол **никогда** не запускает платный запрос сам.

## 6. Правила перехода

- **Старые адреса продолжают работать**: страницы не удаляются, навигация только группирует. Закладки и ссылки из Coauthor/писем не ломаются.
- Первая версия нового интерфейса — это навигация + рабочий стол **без переноса страниц** (дёшево и обратимо).
- Никакой новый экран не вызывает платных запросов без явной кнопки автора и подписи о стоимости.
- Мобильная вёрстка пока не гарантируется (в приложении нигде не проверялась); решение — отдельно.
