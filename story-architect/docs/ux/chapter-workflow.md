## 1. Как это работает сейчас (по коду `C/page.tsx`)

Одна длинная страница. Порядок блоков сверху вниз:

1. Назначение главы → Идея автора → Авторский замысел → Narrative Context
2. Утверждённый план главы (если есть) + Scene Planner
3. Утверждённый план сцен (если есть) + «Сопоставление с Canon» + Writer
4. Редактор черновика (всегда)
5. Проверка непрерывности + Предложения исправлений (если есть текст)
6. Финальное утверждение (если есть текст и не APPROVED/CANON)
7. Canon (если APPROVED), Memory Update (если CANON)
8. **Architect — в самом конце страницы**

Что из этого следует (подтверждено кодом, кроме отмеченного гипотезой):

- **Порядок блоков не совпадает с порядком работы**: Architect нужен первым после замысла, а стоит последним; новому пользователю его не видно без прокрутки.
- **Принятие плана и сцен — на другой странице.** На странице главы нет ссылки на Proposals. По ссылкам интерфейса путь «глава → предложения → глава» — 6 переходов (глава → список глав → проект → Proposals и обратно), с кнопкой «Назад» браузера — 2. Цикл повторяется дважды (план, сцены), то есть от 4 до 12 переходов на каждую главу, прежде чем появится возможность написать черновик через Writer.
- **Дублирование ввода:** замысел вводится двумя блоками; Continuity запускается из двух мест (и первое не работает, пока нет черновика, см. D4).
- **Непонятные действия:** три слова «утверждение» — «Утвердить главу» (APPROVED), «В Canon» (CANON) и «утверждённый план» (Proposal принят); статус `EDITING` показывается в списках, но никогда не выставляется.
- **Принудительная цепочка для Writer:** план утверждён + сцены есть. Писать вручную в редакторе можно всегда, но интерфейс этого не подсказывает.
- **Что уже сделано хорошо** и должно остаться: правка после Canon возвращает статус в APPROVED; утверждение проверяет пометки редактора; применение исправлений Continuity идёт через предпросмотр; Memory Update принимается внутри главы; Writer нельзя запустить для APPROVED/CANON (409); Revise в базу не пишет — исправленный текст попадает в черновик только через сохранение автором.

## 2. Пять этапов

Этапы — это **вкладки рабочего пространства главы**, а не замки. Автор может открыть любой этап в любой момент, вернуться назад, пропустить необязательный. Состояние этапа (✓/•/пусто) считается по данным, ничего нового в БД не хранится.

URL: `/projects/[id]/chapters/[chapterId]?stage=intent|plan|draft|analysis|finish`. Кнопка «Назад» браузера возвращает на предыдущий этап. Без параметра открывается этап, рекомендованный по статусу главы.

### Этап 1 · Замысел
| Компонент | Что делает | Примечание |
|---|---|---|
| Назначение главы (`Chapter.purpose`) | текст-подсказка | без изменений |
| `SaveIdeaForm` | идея автора | подблок «Идея в двух словах» |
| `AuthorIntentPanel` | параметры замысла | подблок «Параметры», ссылка на Референсы |
| `NarrativeContextPanel` | что ИИ знает/не должен раскрывать | свёрнут по умолчанию, раскрывается кнопкой |

Необязательность: этап не блокирует следующие. Состояние: ✓ если заполнена идея или замысел.

### Этап 2 · Планирование
| Компонент | Что делает | Примечание |
|---|---|---|
| `ArchitectButton` | запускает Architect | **первой кнопкой этапа**, с подписью стоимости (из `ROLE_ESTIMATES` AI Usage) |
| Карточка ожидающего предложения `chapter_plan` | принятие/правка/отклонение, ответы на открытые вопросы | **встроенный тот же компонент**, что на странице Proposals; тот же action-маршрут |
| Утверждённый план главы | чтение | как сейчас |
| `ScenePlannerButton` | запускает Scene Planner | показывается после принятия плана |
| Карточка предложения `scene_plan` | принятие | то же |
| Утверждённый план сцен | чтение | как сейчас |

Необязательность: весь этап можно пропустить и писать вручную (см. этап 3). Состояние: ✓ если `planApproved` и есть сцены.

### Этап 3 · Черновик
| Компонент | Что делает | Примечание |
|---|---|---|
| `WriterButton` | генерирует черновик | активен при плане и сценах; иначе объяснение, чего не хватает, со ссылкой на этап 2 |
| `DraftEditor` | редактор, пометки, «Доработать по заметкам» (Revise), «Обсудить с Соавтором» | не меняется |

Блокировка: Writer для APPROVED/CANON остаётся запрещённым (как сейчас, 409) — показывать понятное сообщение. Revise маршрут такого запрета не имеет (**подтверждено**: в `revise/route.ts` нет проверки статуса и нет записи в БД), результат попадает в черновик через ручное сохранение, а оно при статусе CANON возвращает главу к APPROVED (`revertsToApproved`).

### Этап 4 · Анализ
| Компонент | Что делает | Примечание |
|---|---|---|
| Автоматические проверки (новое, без ИИ) | пометки редактора, пустой текст, длина, несохранённые изменения, пересечение с `plan.mustNotHappen` по ключевым словам (**гипотеза**, требует проработки) | запускаются сами, платных запросов нет |
| `ContinuityButton` | проверка черновика против плана и Canon | **один экземпляр**; режим «по сценам» — только после решения по D4 |
| `ContinuitySuggestionsButton` | предложения исправлений и предпросмотр общей правки | как сейчас |
| Сценарный критик (Coauthor) | кнопка «Разбор критиком» для этой главы | открывает панель Coauthor в режиме критика с текущей главой |
| Подсказка разницы | «Continuity сверяет с Canon и планом, Критик оценивает ремесло» | текст-пояснение |

Необязательность: весь этап необязателен; но «Утвердить» предупреждает, если проверка не запускалась (предупреждение, не запрет).

### Этап 5 · Завершение
| Компонент | Что делает | Примечание |
|---|---|---|
| `ApproveChapterButton` | APPROVED | условия не меняются (текст есть, нет пометок) |
| `CanonChapterButton` | CANON, `finalText` = `draftText` | видна только из APPROVED, с подтверждением «это станет основой для памяти и проверок» |
| `MemoryUpdateButton` | извлечение изменений памяти и их принятие внутри главы | как сейчас |
| Итог главы | статус, дата утверждения, ссылки на Canon/Memory | |

## 4. Согласие автора и защита Canon

Каждое из этих действий остаётся **явным нажатием** автора и не объединяется в «одну кнопку»:

1. Запуск любого ИИ (Architect, Scene Planner, Writer, Revise, Continuity, Suggestions, Memory Update, Critic) — рядом ориентировочная стоимость из AI Usage; бюджет $50, Luna по умолчанию, Terra только по запросу.
2. Принятие каждого Proposal — через карточку с `diff`/`impact` (не упрощённая кнопка).
3. Принятие общей правки Continuity — через предпросмотр.
4. APPROVED и CANON — две отдельные кнопки.
5. Никаких «автопереходов»: окончание этапа не запускает следующий.

Автоматически (без платных вызовов) допустимо запускать только детерминированные проверки: наличие пометок, пустота, несохранённые изменения, расчёт индикаторов, расчёт следующей задачи, сборка Narrative Context.
