# p35 · План безопасного перехода к новому интерфейсу

Основа: остальные четыре документа в `docs/ux/`. Проект на согласование; ничего из описанного не реализовано.

## 1. Принципы

1. **Только интерфейс.** Схема БД, миграции, маршруты API, роли ИИ, цены, бюджет $50, Luna/Terra не меняются. Исключение — если автор решит D4 или D6 (см. §6), это отдельные этапы с собственным описанием.
2. **Старые адреса остаются.** Ни одна существующая страница не удаляется, пока новая не заменила её и автор не подтвердил. Навигация только группирует.
3. **Сначала дёшево и обратимо.** Каждый этап можно откатить одним `git revert` без правок данных.
4. **Один этап — один патч** (как p29–p34): `git apply --check`, тесты, `typecheck`, `build`, ручная проверка автором, затем отдельное разрешение на коммит.
5. **Canon Gate неприкосновенен.** Никаких автопринятий; встроенные карточки решений используют те же компоненты и тот же `POST /api/proposals/[id]/action`.
6. **Платных запросов без явной кнопки автора нет.** Новые экраны только читают БД.

## 2. Обязательный набор защитных тестов (до любого этапа)

Прогон `npm.cmd test` должен оставаться зелёным: сейчас 524 теста. Особенно:
- `canon-gate`, `ai-boundary`, `memory-safety`, `lore-fact-apply` — граница Canon;
- `ai-usage*`, `ai-usage-audit` — учёт и бюджет;
- `narrative-context`, `narrative-writer`, `plot-map` — вехи и спойлеры;
- `coauthor*` — Coauthor, критик, потоки;
- `chapter-draft-edit`, `chapter-revise`, `editor-marks` — редактор.

Новые тесты по этапам указаны ниже. Рендер React-компонентов в проекте сейчас тестируется только через чистые функции (`coauthor-ui.test.ts`), поэтому для новых экранов логику (расчёт индикаторов этапов, следующей задачи, список ссылок навигации) нужно выносить в чистые функции `lib/ux/*.ts` и тестировать их; сама вёрстка проверяется вручную автором.

## 3. Порядок этапов

### p36 · Навигация и рабочий стол (малый риск, **обязательно**)
Что:
- Верхняя навигация проекта в существующем `P/layout.tsx`: Рабочий стол, Книги и главы, Вселенная, Сюжет, Центр решений, Инструменты; счётчик ожидающих предложений.
- Рабочий стол: заменить сетку карточек на сводку (статусы глав, следующая задача, ожидающие решения, расход ИИ). Старую сетку оставить как раздел «Все разделы» на этой же странице.
- Мелкие исправления без дизайна: ссылка «создать проект» на Dashboard → `/projects/new`; «← На главную» на `/ai-usage` → в проект; ссылка «Открыть предложения» после Architect/Scene Planner.
- Чистые функции: `nextTask(chapters, proposals)`, `chapterStageState(chapter)`, `navItems(projectId)`.

Не затрагивает: страницы-источники, API, данные.
Тесты: `nextTask` для всех статусов (IDEA…CANON, с/без плана, сцен, черновика, Memory Update); `navItems` содержит все 15 прежних маршрутов (ничего не потерялось); `isDockHidden` на `/export` скрывает и навигацию.
Откат: `git revert`.
Риск: навигация в печатном виде экспорта — скрыть как панель Coauthor.

### p37 · Рабочее пространство главы (средний риск, **обязательно**)
Что:
- Оболочка с пятью этапами и `?stage=`; существующие компоненты монтируются в этапы **без изменения кода**.
- Architect переезжает на этап «Планирование».
- Один `ContinuityButton` (решение по D4 принято заранее, см. §6).
- Подпись стоимости на кнопках ИИ (из `ROLE_ESTIMATES`).
- Встроенное принятие плана/сцен — **только если** карточка предложения из `proposals/page.tsx` может быть вынесена в отдельный компонент без изменения поведения. Иначе этот пункт идёт в p38 отдельным патчем (страница 1355 строк, риск регрессии).

Не затрагивает: `lib/canon/write.ts`, схемы, маршруты.
Тесты: индикаторы этапов (`chapterStageState`); переключение этапов не теряет несохранённый текст редактора (проверка ручная + чистая функция «есть ли несохранённое»); существующие тесты.
Откат: `git revert`; старая страница главы остаётся доступной как запасной маршрут на время перехода (например, `?stage=all` показывает все блоки подряд, как сейчас).
Риск: потеря несохранённого текста в `DraftEditor` при смене вкладки (сохранение ручное). Митигация: вкладки скрывают, а не размонтируют; предупреждение при уходе.

### p38 · Центр решений и встроенные карточки (средний/высокий риск, **желательно**)
Что: вынести карточку предложения в общий компонент; использовать её на этапе «Планирование» и в Центре решений; добавить историю решений (принятые/отклонённые) — только чтение `Proposal`.
Тесты: `canon-gate`, `plan-answers`, `open-question-proposals`; новый — встроенная карточка вызывает тот же action-маршрут.
Риск: самый высокий. Порядок: сначала вынести без изменения поведения, затем подключать на новом месте.

### p39 · «Вселенная» и «Сюжет» как вкладки (малый риск, **желательно**)
Что: группировка существующих страниц во вкладки (Материалы: Story Bible/Lore/Референсы; Сущности; Canon/Память; Сюжет: Карта/Линии/Хронология). Страницы не переписываются.
Тесты: список вкладок содержит все прежние маршруты; существующие.

### p40+ · Карточка сущности (средний риск, **желательно**; изображения — **необязательно**)
Что: единая карточка по `entityType`/`entityId`: факты, состояния, отношения, события, источники, ожидающие предложения. Чтение; правка — только через Proposal.
Изображения: в схеме нет полей под них; потребуют миграции и решения о хранении файлов — отдельный этап по запросу автора.
Тесты: сборка карточки из фикстур; статус каждой строки обязателен.

### Необязательно
- Общий каркас страниц только для чтения (`PageShell` используют 3 из 5), единый `@/lib/db` вместо 20 собственных `new PrismaClient()`.
- Подтверждение перед «В Canon», автоматические проверки текста по ключевым словам.
- Мобильная вёрстка.

## 4. Что намеренно не делается

- Не удаляются таблицы (в том числе 11 без обращений в коде), страницы, маршруты и кнопки.
- Не объединяются Proposal-цепочки и не вводится «принять всё».
- Не меняются промпты, роли, лимиты, цены, бюджет.
- Не вводятся автоматические запуски ИИ при открытии экрана.
